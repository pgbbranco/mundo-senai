Conceito

O que é front-end

É tudo o que roda no navegador e aparece na tela de quem usa o produto.

  • HTML define a estrutura e o significado do conteúdo.
  • CSS define a aparência: cor, tipografia, espaço e layout.
  • JavaScript define o comportamento: cliques, formulários e animações.

Servidores e bancos de dados ficam fora desta conversa. Aqui o foco é a interface.

Em uma frase: front-end transforma regras e conteúdo em uma experiência que a pessoa consegue perceber, entender e usar.

Conceito

As três camadas no mesmo botão

<button class="comprar">Comprar</button>

.comprar { background: #0f766e; color: #fff; }

comprar.onclick = () => abrirCarrinho()
  • O HTML diz que aquilo é um botão, e o navegador já entrega foco e teclado.
  • O CSS decide como ele parece.
  • O JavaScript decide o que acontece ao clicar.
Importância

Um bom front-end muda o resultado

  • Primeira impressão: a pessoa julga a página em frações de segundo, antes de ler.
  • Confiança: interface descuidada sugere produto descuidado.
  • Uso: se for difícil de ler ou de clicar, a pessoa desiste.
  • Custo: corrigir problemas de interface depois de pronto sai mais caro.
  • Alcance: uma interface bem feita funciona para mais gente, em mais aparelhos.
Importância · Desempenho

Rápido também faz parte da interface

O Google mede a experiência de carregamento com três números, chamados Core Web Vitals.

  • LCP: o maior elemento aparece em até 2,5 segundos.
  • INP: a página responde a um clique em até 200 milissegundos.
  • CLS: o layout não pula durante o carregamento (até 0,1).

Imagens sem tamanho definido, fontes pesadas e JavaScript demais são as causas mais comuns de nota baixa.

Importância · Mitos

Quatro mitos sobre front-end

  • “É só deixar bonito.” Boa parte do trabalho é estrutura, estados, erros e acessibilidade.
  • “Dá para deixar para o fim.” Refazer a interface depois de pronta custa muito mais.
  • “Funciona na minha tela.” Outras telas, teclados e conexões contam outra história.
  • “A IA gera tudo.” Ela gera um começo. Alguém ainda precisa decidir e revisar.
Parte 2 de 3 · Responsividade

Uma página, vários tamanhos de tela

Celular, tablet, notebook, monitor largo, projetor como este. O layout precisa se ajustar a todos sem quebrar nem exigir zoom.

  • Comece pelo celular e amplie depois (mobile-first).
  • Use rem, % e clamp() no lugar de larguras fixas em pixel.
  • Monte o layout com flex e grid e troque o arranjo com media queries.
  • Não esqueça da tag meta viewport no HTML.

Mais que encolher: responder ao tamanho da tela também pode significar reorganizar a ordem, esconder o secundário, aumentar áreas de toque ou trocar a forma de interação.

Responsividade

Na prática e nos erros comuns

.pagina {
  padding: clamp(1rem, 4vw, 3rem);
}
@media (min-width: 48rem) {
  .grade { grid-template-columns: 1fr 1fr; }
}
  • Largura fixa em pixel gera rolagem horizontal no celular.
  • Texto pequeno demais obriga a pessoa a dar zoom.
  • Botões miúdos e colados são difíceis de tocar: mire em 44 px de área.
  • Teste no celular de verdade, não só na janela redimensionada.
Responsividade · Layout

Flex para uma linha, grid para a malha

.barra { display: flex; gap: 1rem; }

.galeria {
  display: grid;
  grid-template-columns:
    repeat(auto-fit, minmax(16rem, 1fr));
}
  • Flexbox distribui itens em uma direção: menus, barras, linhas de botões.
  • Grid organiza linhas e colunas ao mesmo tempo: galerias, painéis, páginas inteiras.
  • Com auto-fit e minmax() as colunas se ajustam sozinhas, sem media query.
Acessibilidade

Interface que funciona para todo mundo

Cerca de 1 em cada 6 pessoas no mundo vive com alguma deficiência, segundo a OMS. Fora isso, qualquer um passa por limitações temporárias: sol na tela, uma mão ocupada, um braço engessado.

Acessibilidade faz parte do trabalho de deixar a interface funcionando, junto com layout e desempenho.

Teste simples: tente usar a página só com teclado, aumente o zoom para 200% e desative imagens. Se o sentido desaparecer, há trabalho de front-end a fazer.

Acessibilidade

O básico que resolve muito

  • HTML semântico: button, nav, main e títulos em ordem.
  • Contraste: pelo menos 4,5 para 1 em texto comum (WCAG AA).
  • Teclado: tudo deve funcionar sem mouse, com o foco sempre visível.
  • Imagens: texto alternativo para as que informam algo.
  • Formulários: todo campo com um label associado.
  • Cor: nunca use só a cor para passar uma informação.
  • Movimento: respeite prefers-reduced-motion.
Acessibilidade · Teclado

Teclado e foco visível

:focus-visible {
  outline: 3px solid #f59e0b;
  outline-offset: 2px;
}
  • Quem não usa mouse navega com Tab, Enter, Espaço e as setas.
  • Sem um contorno visível a pessoa não sabe onde está. Nunca use outline: none sozinho.
  • A ordem do foco deve seguir a ordem da leitura.
  • Um link “pular para o conteúdo” poupa dezenas de tabs a cada página.
Acessibilidade · Contraste

Contraste entre texto e fundo

  • 4,5 para 1 no texto comum (WCAG AA).
  • 3 para 1 em texto grande e em bordas de botões e campos.
  • 7 para 1 no nível AAA, o mais exigente.
  • Cinza claro sobre branco e amarelo sobre branco costumam reprovar.
  • Cor sozinha não basta: some um ícone, um texto ou um sublinhado.

Dica: no painel do celular, a seção de cores mostra a razão de contraste em tempo real. Use para saber se o novo visual passa.

Acessibilidade · Leitores de tela

Leitores de tela e ARIA

Leitores de tela falam o que o HTML descreve. Se tudo for div, não há o que falar.

  • Prefira o elemento nativo: button, a, input, nav.
  • Use ARIA só quando o HTML não resolve, por exemplo aria-label em um botão que só tem ícone.
  • A primeira regra do ARIA: se um elemento nativo faz o trabalho, não use ARIA.
  • Escreva o alt pensando em quem não vê: descreva a função da imagem, não a aparência.
Parte 3 de 3 · AI Slop

O que é AI slop

É o resultado genérico de uma ferramenta de IA usada sem direção: um site com a cara da média de todos os outros. Funciona, mas ninguém decidiu nada.

O problema aparece quando falta decisão humana sobre o que a interface precisa dizer e para quem. A ferramenta é a mesma, o resultado muda com a direção.

Definição de trabalho: conteúdo produzido em volume, com pouca revisão, contexto ou responsabilidade editorial. Usar IA com direção e revisão fica de fora.

AI Slop · Causas

Por que o resultado fica igual

  • Os modelos aprendem com milhões de páginas e tendem a devolver a média delas.
  • Um pedido vago (“faça uma landing page moderna”) tem uma resposta média.
  • Os mesmos kits de componentes e as mesmas fontes padrão aparecem em tudo.
  • Gerar é rápido, então a revisão é pulada.
  • Ninguém definiu antes quem usa a página e o que essa pessoa precisa fazer.
Sinais visuais

O que denuncia no visual

  • Gradiente roxo ou índigo e manchas brilhantes de fundo.
  • A mesma fonte (quase sempre Inter) em todos os textos.
  • Emojis no lugar de ícones.
  • Cartões iguais, com o mesmo canto arredondado e a mesma sombra.
  • Cartão dentro de cartão, vidro fosco e faixa colorida na lateral.
  • Imagem genérica de pessoa sorrindo para um notebook, sem relação com o produto.
  • Excesso de brilho, blur e efeitos que competem com o conteúdo.

Um sinal sozinho prova pouco. O alerta acende quando várias escolhas genéricas se acumulam sem razão clara.

Estrutura e texto

O que denuncia na estrutura e no texto

  • Roteiro fixo: título centralizado, três cartões iguais, botão e rodapé.
  • Depoimentos e logos de clientes inventados.
  • Números redondos sem fonte, como “10x mais rápido”.
  • Frases vazias: “revolucione”, “eleve”, “mergulhe”.
  • O vício do “não é só X, é Y” e travessões em excesso.
Sinais no código

O que denuncia no código

<div class="btn" onclick="enviar()">
  Enviar
</div>
  • div clicável no lugar de button: sem foco, sem teclado, sem leitor de tela.
  • Imagem sem alt ou com alt="imagem".
  • Campo que usa o placeholder no lugar do label.
  • Camadas e mais camadas de div sem nenhum título ou região.
  • Cores fixas espalhadas, em vez de variáveis CSS reaproveitadas.
Exemplo

O mesmo produto, duas decisões

Genérico: “Revolucione a sua gestão com o poder da inteligência artificial.”

Específico: “Veja o que falta na prateleira da padaria antes de abrir.”

  • A primeira frase serviria para qualquer empresa. A segunda só serve para uma.
  • A segunda cita uma tarefa real, um momento real e um benefício que dá para conferir.
  • O visual segue o mesmo caminho: cor, foto e fonte vindas do negócio, não do modelo.
Como evitar

Como fugir do genérico, antes de gerar

  • Comece pelo problema real e pelo conteúdo real, não pelo visual.
  • Escolha uma cor de marca e duas fontes de propósito.
  • Varie a hierarquia e a largura dos blocos.
  • Use uma biblioteca de ícones só, ou nenhum ícone.
Como evitar

Como fugir do genérico, ao revisar

  • Escreva texto específico e só cite dados que dá para verificar.
  • Teste com pessoas e revise tudo à mão.
  • Peça à IA alternativas e estrutura, mas preserve a decisão editorial no time.
  • Troque abstrações por evidências: uma tarefa real, um usuário real e uma mensagem concreta.

Regra prática: se você remover o logotipo e o texto, o layout ainda deveria revelar para quem aquela interface foi feita.
